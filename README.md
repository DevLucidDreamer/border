# BORDER — 경계선지능 청년을 위한 AI 학습 도우미

> **강의를 녹음하거나 PDF를 올리기만 하면, AI가 "쉬운 글 + 읽어주는 음성 + 키워드 그림 + 복습 문제"로 자동 정리하고, 복습 시점까지 앱이 알아서 챙겨 주는 학습 앱.**
>
> 사용자가 하는 일은 단순합니다 — **[녹음하기]** 로 강의를 그 자리에서 녹음하거나 **[자료 넣기]** 로 음성 파일·PDF를 올리면 AI가 알아서 정리하고, **[학습하기]** 를 누르면 복습 시점까지 앱이 챙깁니다.

- 🌐 **웹 데모 (실제 작동)**: https://border-cxs.pages.dev
- 📱 **네이티브 데모**: iOS / iPadOS · Android (Flutter 단일 코드베이스)
- 🧩 **상태**: 입력 → AI 정리 → 3단계 복습까지 **End-to-End 실동작**. 실제 AI(음성인식·요약·음성합성·삽화) 연동 완료.

## 1. 문제 정의 — 왜 만들었나

### 대상: 경계선지능인(BIF, Borderline Intellectual Functioning)
지능지수(IQ) 약 **71~84** 구간으로, 지적장애(70 이하)에는 해당하지 않지만 평균에도 못 미치는 사람들입니다. 정규분포상 **전체 인구의 약 13~14%**(국내 추정 수백만 명)에 이르지만, 장애 등록 대상이 아니어서 **복지·교육 지원의 사각지대**에 놓여 있습니다.

### 실재하는 페인포인트 (구체적)
경계선지능 청년이 일반 강의·학습 콘텐츠를 따라가지 못하는 이유는 "노력 부족"이 아니라 **인지 특성**입니다.

| 페인포인트 | 무엇이 문제인가 | 기존 학습앱이 놓치는 지점 |
|---|---|---|
| **정보 과부하** | 긴 강의·원문을 한 번에 처리하기 어렵다 | 원문·자막을 그대로 보여 줌 → 오히려 부담 가중 |
| **복습 관리 실패** | "언제 무엇을 복습할지" 스스로 계획·유지하지 못한다 | 복습 목록/폴더를 사용자가 직접 뒤져야 함 |
| **선택지 과부하** | 메뉴·설정·버튼이 많으면 진입 자체를 포기한다 | 기능이 많을수록 좋다는 통념으로 UI가 복잡 |
| **문해력 격차** | 딱딱한 문어체 요약은 여전히 어렵다 | "요약 = 짧게"일 뿐, 쉬운 말로 바꾸지 않음 |

### 핵심 인사이트
> **"기능을 더하는 것"이 아니라 "사용자가 내려야 하는 결정을 없애는 것"**이 이 대상에게는 접근성이다.
> BORDER는 그래서 화면 흐름을 **입력(녹음/자료 넣기) → 학습, 두 개의 루프**로 압축하고, 복습 판단을 **앱이 대신** 한다.

## 2. 솔루션 — 어떻게 푸는가

### 세 개의 버튼, 두 개의 루프

홈 화면의 세 버튼은 **입력 루프**(녹음하기 · 자료 넣기)와 **학습 루프**(학습하기) 두 가지로 묶입니다.

- **[녹음하기]** — 강의를 **앱에서 그 자리에서 바로 녹음**. 필기가 어려운 사용자가 수업 중 버튼 한 번만 누르면 되는 핵심 입력.
- **[자료 넣기]** — 이미 가진 **음성 파일이나 PDF를 업로드**.
- **[학습하기]** — 오늘 할 복습·학습을 앱이 자동으로 진행.

```
┌─────────────────────────────────────────────────────────────┐
│  [녹음하기]  강의를 앱에서 바로 녹음                         │
│  [자료 넣기]  이미 있는 음성 파일 · PDF 업로드              │
│       │                                                      │
│       ▼   AI가 자동으로:                                     │
│   ┌──────────────────────────────────────────────┐          │
│   │ ① 쉬운 글로 재구성 (스토리텔링 문체)          │          │
│   │ ② 그 글을 다정한 목소리로 읽어주는 음성        │          │
│   │ ③ 핵심 키워드 + 뜻 + 이해를 돕는 삽화          │          │
│   │ ④ OX / 응용 문제 (3단계 복습용)                │          │
│   └──────────────────────────────────────────────┘          │
│       │  → "N단원" 한 개로 저장                              │
│                                                              │
│  [학습하기]  누르기만 하면:                                  │
│       │  오늘 마감된 복습 → 새 단원 순으로 앱이 자동 진행     │
│       ▼                                                      │
│   복습 1단계(키워드) → 2단계(OX) → 3단계(응용) → 완료        │
│   (정답이면 다음 단계 / 오답이면 한 단계 뒤로, 자동 재예약)  │
└─────────────────────────────────────────────────────────────┘
```

사용자는 **목록을 탐색하지 않습니다.** "학습하기"를 누르면 **오늘 할 것**(마감 복습 + 신규 단원)이 알아서 순서대로 나오고, 오늘 할 게 없으면 *"오늘 복습·학습을 마쳤어요"* 안내만 뜹니다.

## 3. MVP 완성도

**"실제로 작동하는 데모"** — 목업이 아니라 입력부터 복습까지 전 구간이 실동작합니다.

### 실동작 체크리스트
- [x] **입력 3종**: 앱 내 녹음 / 음성 파일 업로드 / PDF 업로드
- [x] **실제 음성인식(STT)**: OpenAI Whisper 연동
- [x] **실제 AI 정리**: Claude Sonnet 5 — 원문을 쉬운 글 + 키워드 + OX/응용 문제로 변환
- [x] **실제 음성 합성(TTS)**: OpenAI `gpt-4o-mini-tts`(느린학습자용 말투 지시), CLOVA Voice 폴백
- [x] **키워드 삽화 생성**: OpenAI 이미지 모델
- [x] **PDF 텍스트 추출** + 스캔 PDF는 Claude 문서 OCR 폴백
- [x] **시간표 사진 OCR** → 녹음 시각으로 과목 자동 매칭
- [x] **3단계 간격 반복 복습 엔진** (정답/오답에 따른 자동 재예약)
- [x] **로컬 영속화**: 앱을 껐다 켜도 단원·복습 상태 유지 (Hive)
- [x] **멀티플랫폼 배포**: iOS/iPad 네이티브 + **웹 실배포(Cloudflare Pages)**
- [x] **데모 안전장치**: API 키가 없어도 **Mock 데이터로 전체 흐름이 끝까지 동작** → 시연 실패 없음
- [x] **데모 모드**: 시연 중 날짜를 앞당겨 복습 주기를 즉석에서 시연 가능

### "무너지지 않는 데모"를 위한 설계
- **키 없으면 Mock 자동 전환**: 실제 AI 키가 없거나 네트워크가 끊겨도 샘플 콘텐츠로 전 화면을 시연할 수 있습니다.
- **단계별 예외 격리**: 삽화 생성이 실패해도 카드는 그림 없이 진행되는 등, 한 단계 실패가 전체를 막지 않습니다.
- **웹/네이티브 동시 지원**: 설치 없이 브라우저(https://border-cxs.pages.dev)로 바로 체험 가능합니다.

## 4. 핵심 기능

| 기능 | 설명 |
|---|---|
| **강의 녹음 (녹음하기)** | 수업 중 버튼 한 번으로 강의를 앱에서 바로 녹음. 필기가 어려운 사용자의 핵심 입력 수단 → 자동으로 텍스트화·정리로 이어짐 |
| **자료 업로드 (자료 넣기)** | 이미 가진 음성 파일·PDF를 올려 동일한 정리 파이프라인에 투입 |
| **쉬운 글 재구성** | 요약이 아니라 *쉬운 말로 다시 쓰기*. 정보량을 줄이고 스토리텔링 문체로 바꿔 인지 부담을 낮춤 |
| **읽어주는 음성** | 쉬운 글을 "다정하고 또렷하게, 조금 천천히" 읽어 주는 음성. 문해력 격차 보완 |
| **키워드 카드 + 삽화** | 핵심 단어 · 뜻 · 이해를 돕는 그림. 시각적 기억 앵커 |
| **3단계 복습** | 1단계 키워드 재인지 → 2단계 OX → 3단계 응용. 앱이 시점을 관리 |
| **자료 1건 = 단원 1개** | AI가 내용을 임의로 쪼개거나 합치지 않음 → 학습 단위가 예측 가능하고 단순 |
| **시간표 연동** | 시간표 사진을 찍어두면 녹음 시각으로 어떤 과목인지 자동 분류 |

## 5. 기술 아키텍처

### 스택
- **프레임워크**: Flutter (iOS / Android / Web 단일 코드베이스), Dart 3.8+
- **AI**:
  - 요약·문항·과목분류·시간표 OCR — **Anthropic Claude Sonnet 5**
  - 음성인식(STT) — **OpenAI Whisper**
  - 음성합성(TTS) — **OpenAI gpt-4o-mini-tts** (폴백: **NAVER CLOVA Voice**)
  - 삽화 — **OpenAI 이미지 모델**
- **저장소**: **Hive**(로컬 전용, 백엔드 서버 없음) + `flutter_secure_storage`(암호화 키 보관)
- **문서 처리**: `syncfusion_flutter_pdf`(텍스트 추출), 스캔 PDF는 Claude 문서 OCR
- **웹 배포**: **Cloudflare Pages** + Pages **Functions**(AI 프록시)

### 전체 흐름
```
[입력] 녹음 / 음성파일 / PDF
        │
        ▼
 RecordingController ── 원본 로컬 저장(Lecture)
        │  STT(음성) 또는 PDF 텍스트추출 → 원문(rawTranscript)
        ▼
 AiOrchestrator.run() ── 원문 → 쉬운글 → (키워드카드 + OX·응용문제) + 음성 + 삽화
        │
        ▼
 UnitRepository.save(Unit)   ★학습 콘텐츠 확정 (Hive: units)
        │
        ▼
[학습] LearnController.start()
        │  ① 오늘 마감 복습(due, 낮은 단계 우선)  ② 아직 안 배운 신규 단원
        ▼
 복습 1→2→3단계 → 신규 학습
        ├─ 신규 학습 완료 → Unit.learned=true + 1단계 복습 등록
        └─ 복습 응답     → ReviewEngine.apply() 결과 저장
```

### 디렉터리 구조 (`lib/`)
| 경로 | 역할 |
|---|---|
| `main.dart` | 진입점. `runZonedGuarded`로 감싸 전역 예외 안전화 → `LocalStore.init()` → `runApp` |
| `core/` | `service_locator.dart`(의존성 조립·키 유무로 실AI/Mock 자동 선택), `app_config.dart`(키·엔드포인트), `platform_media.dart`(웹/네이티브 미디어 분기), `app_clock.dart`(데모 날짜) |
| `models/` | `unit`, `review_schedule`, `lecture`, `keyword_card`, `quiz`, `enums` — 전부 `toMap/fromMap` 자체 직렬화 |
| `data/` | Hive 박스 초기화(`local_store.dart`) + 저장소(`*_repository.dart`) |
| `controllers/` | `recording_controller`(입력→정리), `learn_controller`(학습→복습) |
| `services/ai/` | `ai_orchestrator` + `pipeline_stages`(인터페이스) + `claude/` `openai/` `clova/` `mock/` 구현 |
| `services/stt/` · `files/` · `audio/` · `ocr/` · `review/` | 음성인식, 파일 임포트, 녹음, 시간표 OCR, 복습 엔진 |
| `ui/` | `home`, `recording`, `learn`, `timetable_*`, `splash` 화면 |
| `functions/api/[[path]].js` | **Cloudflare Pages Function** — 웹 AI 프록시 (아래 보안 참조) |

### 3단계 복습 엔진 (`review_engine.dart`, 순수 로직)
- **학습 완료** → 1단계 등록, `dueDate = 완료시각 + 1일`
- **정답**: 마지막(3)단계면 `completed`, 아니면 `stage+1`(다음날)
- **오답**: `stage-1`(1단계는 유지), 다음날 재예약
- `reviewInterval`(기본 1일)을 줄이면 데모에서 즉시 확인 가능

## 6. 보안 및 안전성

학습 데이터는 **개인의 인지 특성·학습 이력**이라는 민감정보에 해당하므로, "수집하지 않는 것"을 기본 원칙으로 설계했습니다.

### 6.1 데이터 최소수집 — 백엔드 서버가 없다
- 모든 학습 데이터(녹음·원문·단원·복습 상태)는 **기기 로컬(Hive)에만** 저장됩니다. **중앙 서버로 전송·수집하지 않습니다.**
- 계정·로그인·회원가입이 없습니다 → **유출될 개인식별정보 자체가 존재하지 않습니다.**

### 6.2 로컬 저장 암호화 (네이티브)
- 모든 Hive 박스는 **AES로 암호화**됩니다.
- 32바이트 암호화 키는 **iOS Keychain / Android Keystore**(`flutter_secure_storage`)에 보관 → 앱 샌드박스 밖으로 나가지 않습니다.
- iOS **Data Protection**(NSFileProtectionComplete)이 파일을 한 번 더 감싸, 기기 잠금 상태에서는 디스크의 학습 데이터가 평문으로 남지 않습니다.

### 6.3 API 키 비노출 (웹) — 프록시 패턴
웹은 브라우저에 코드가 노출되므로, API 키를 **절대 클라이언트에 두지 않습니다.**
- 웹앱은 같은 오리진의 **Cloudflare Pages Function(`/api/*`)** 을 호출합니다.
- 이 함수가 **서버 측 시크릿**(Cloudflare 환경변수 `ANTHROPIC_API_KEY`·`OPENAI_API_KEY`)으로 키를 주입해 실제 provider로 중계합니다.
- 이로써 **① 브라우저 키 노출**과 **② CORS 차단**을 동시에 해결하고, 허용 경로 화이트리스트로 오픈프록시 오남용을 제한합니다.
- 웹 빌드용 `.env`는 **비워 둡니다** → 번들에 실제 키가 실리지 않습니다.

### 6.4 운영 안정성
- 앱 전체를 `runZonedGuarded`로 감싸 미처리 예외가 화면을 죽이지 않도록 했고, 파이프라인 각 단계의 실패를 격리했습니다.
- (추가 예정) 프록시단 인증·레이트리밋은 Cloudflare Access / Rate Limiting으로 확장 가능하도록 분리해 두었습니다.

## 7. 시장성 및 사업화 가능성

### 7.1 시장 규모
- **1차 타깃(경계선지능)**: 정규분포상 인구의 약 13~14% (국내 추정 수백만 명). 장애 미등록 사각지대라 **전용 솔루션의 공급이 거의 없는 미개척 시장**입니다.
- **인접 확장 시장**: 느린 학습자(경계선 진단 밖 포함), 학습장애·ADHD·난독증, 문해력 지원이 필요한 **중장년·노년층** — "정보 과부하를 줄이고 쉬운 말로 바꾼다"는 동일 엔진이 그대로 적용됩니다.

### 7.2 수익 구조
| 모델 | 대상 | 내용 |
|---|---|---|
| **B2G / B2B** | 특수교육기관·복지관·지자체 | 기관 라이선스·연간 계약. 사각지대 복지 정책과 연계(정부 조달·바우처) |
| **B2B2C** | 학원·평생교육·에듀테크 | 기존 콘텐츠를 "쉬운 버전"으로 변환하는 부가 기능/API 제공 |
| **B2C 구독** | 학습자·보호자 | 월 구독(무제한 변환·복습 관리), 무료 티어 + 프리미엄 |

### 7.3 확장성

BORDER의 확장성은 **수익모델 · 시장 · 고객** 세 축에서 동시에 열려 있으며, 그 바탕에는 provider·과목에 독립적인 파이프라인 구조가 있습니다.

#### ① 수익모델 확장성 — 한 사용자당 매출(ARPU)을 여러 단계로 키운다
- **무료 → 구독(B2C)**: 무료 티어(월 변환 횟수 제한)로 진입 → 무제한 변환·복습 관리 프리미엄 구독으로 전환.
- **거래형(Transactional) 매출**: "쉬운 버전 변환"을 건당 과금(문서·강의 1건당)하는 종량제 → 사용량이 곧 매출.
- **라이선스(B2G/B2B)**: 기관 단위 좌석(seat) 라이선스·연간 계약. 사각지대 복지 정책·바우처와 연계한 조달형 매출.
- **플랫폼/API(B2B2C)**: 변환·복습 엔진을 **API·SDK로 개방** → 타 에듀테크·출판·LMS가 자사 콘텐츠에 "쉬운 모드"를 붙이는 사용량 기반 매출.
- **데이터 인사이트(옵트인)**: 개인정보 없이 집계된 "어떤 개념이 어려운가" 학습 난이도 데이터를 교재·커리큘럼 개선 컨설팅으로 (동의 기반) 제공.
> 하나의 엔진에서 **구독·종량·라이선스·API**가 동시에 나오므로, 고객군에 맞춰 수익 방식을 갈아끼울 수 있습니다.

#### ② 시장 확장성 — 대학에서 시작해 교육·훈련·복지 시장 전반으로
초기에는 **대학 교육 시장**을 대상으로 서비스를 제공하지만, 이후 **평생교육기관·온라인 교육 플랫폼·기업 교육·공공 교육기관·복지기관** 등 다양한 교육·훈련 시장으로 진출할 수 있습니다. 또한 **대학 장애학생지원센터·평생교육원·직업훈련기관** 등 기관 단위 시장도 공략할 수 있어 시장 확장성이 높습니다.

- **주요 진입 시장**: 특수교육·장애학생 지원 시장 → 평생교육 시장 → **시니어 에듀테크 시장**.
- **시니어 에듀테크 확장**: 영상 첨부 기능(아래 고객 확장성 참조)을 추가하면 영상 소비 중심의 시니어 에듀테크 시장으로 확장이 가능합니다.
- **기관(B2G/B2B) 채널**: 장애학생지원센터·복지관·직업훈련기관 등 기관 단위 도입은 사각지대 복지 정책·예산과 맞물려 조달형 시장을 형성합니다.

#### ③ 고객 확장성 — 경계선지능에서 시작해 유사 학습자 전반으로
초기에는 **경계선지능 청년**을 핵심 고객으로 설정하지만, 이후 학습 과정에서 **유사한 어려움을 겪는 다양한 학습자**로 고객층을 확대할 수 있습니다. 예를 들어 **학습장애 학생, ADHD 학습자, 난독증 학습자, 학습 능력이 떨어지는 고령층**까지 서비스를 제공할 수 있습니다. 즉, **동일한 서비스를 더 많은 고객군에게 제공**할 수 있다는 점에서 고객 확장성이 높습니다.

| 고객군 | 확장 방식 | 필요 대응 |
|---|---|---|
| **학습장애 학생 · ADHD 학습자** | 현재 기능을 그대로 사용 | **추가 개발 없이 즉시 사용 가능** |
| **난독증 학습자** | 이미지 활용을 높여, 스토리텔링의 말풍선을 **영상으로 대체**해 학습 지원 | 영상 기반 스토리텔링 강화 |
| **고령층** | PDF 자료보다 **영상 자료로 정보를 소비하는 경향**이 커, 영상 콘텐츠로 지원 | **영상 첨부 기능 추가** (→ 시니어 에듀테크 시장과 연결) |

> 코어 가치("쉽게 바꿔 이해를 돕는다")가 특정 장애·연령에 묶여 있지 않아, **동일 제품으로 사용자층을 계속 넓힐 수 있습니다.**

#### 이를 뒷받침하는 기술·비용 구조
- **파이프라인 추상화**: AI 구현이 인터페이스(`pipeline_stages`)로 분리 → provider 교체·비용 최적화·신규 과목 추가가 **코드 변경 최소화**로 가능(현재도 키 유무로 실AI/Mock 자동 전환).
- **로컬-퍼스트 저비용**: 서버·DB 운영비가 없어 사용자 증가에도 인프라 비용이 선형적으로 늘지 않고, 변동비는 AI 호출에 한정 → 확장 시 **마진 구조가 유리**합니다.

## 8. 실행 및 배포 방법

### 로컬 실행 (네이티브)
```bash
flutter pub get
# 키가 있으면 실제 AI로, 없으면 Mock으로 동작
flutter run \
  --dart-define=ANTHROPIC_API_KEY=sk-ant-... \
  --dart-define=OPENAI_API_KEY=sk-...
```
> 키 없이 `flutter run`만 해도 Mock 데이터로 전 흐름이 동작합니다. `.env` 파일로 키를 주입할 수도 있습니다.

### 웹 배포 (Cloudflare Pages)
```bash
flutter build web
# 저장소 루트의 functions/ 가 Pages Functions로 함께 배포됨
```
Cloudflare Pages 설정:
1. 빌드 산출물: `build/web`, 저장소 루트의 `functions/` 자동 인식
2. **환경변수(Secret)**: `ANTHROPIC_API_KEY`, `OPENAI_API_KEY` 설정 → 웹에서 실제 AI 동작
3. **웹 빌드용 `.env`는 비워 둘 것** (키 노출 방지)

### 주요 환경변수
| 키 | 용도 | 기본값 |
|---|---|---|
| `ANTHROPIC_API_KEY` | Claude(요약·문항·OCR) | 없으면 Mock |
| `OPENAI_API_KEY` | Whisper(STT)·TTS·이미지 | 없으면 Mock |
| `CLAUDE_MODEL` / `STT_MODEL` / `TTS_MODEL` / `TTS_VOICE` / `IMAGE_MODEL` | 모델 선택 | 코드 내 기본값 |
| `CLOVA_CLIENT_ID` / `CLOVA_CLIENT_SECRET` | 폴백 TTS | 선택 |
